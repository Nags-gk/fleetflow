Same floor, same robots, same orders. One fleet routes around traffic jams before they form.

Both warehouses below run the same Rust planner compiled to WebAssembly: Hungarian task assignment and collision-free space-time A*. The right-hand fleet also asks a small neural network where robots will be stuck waiting over the next 8 ticks, and routes around those cells.

What happens every planning cycle

  1. Assign orders

    Idle robots are matched to open orders with the Hungarian algorithm, the exact solution of the assignment linear program, minimising total drive distance. A greedy matcher is kept as a baseline.

  2. Forecast congestion

    A 7.7k-parameter dilated CNN reads a 5-channel snapshot of the floor (pods, stations, robots, destinations, next 8 steps of intent) and predicts where robots will be forced to wait. Trained in PyTorch, exported to ONNX, run here with ONNX Runtime Web.

  3. Plan collision-free paths

    Windowed prioritized planning with space-time A* and a vertex/edge reservation table. Forecast hotspots add cost; each robot's own footprint is removed first so it is not pushed off its own route. A conservative fallback pass guarantees a feasible plan every cycle.

  4. Execute and verify

    Robots execute the first steps, re-planning on a fixed cadence or as soon as one finishes a leg. An independent validator checks every tick for two robots in one cell or swapping places.
